# Themes 与 Workshops 分栏管理设计

## 背景

摄影后台目前将 Theme 与 Workshop 作为照片筛选类型放在同一套总览里。这样可以筛选照片，但不能清晰管理两类内容，也没有面向内容本身的新增入口。与此同时，后台文字、表单标签和辅助信息整体偏小，前台阅读层级也需要更舒展。

## 目标

- 在后台将 Themes 与 Workshops 作为两个独立栏目。
- 每个栏目都支持列表浏览、新增、编辑、发布状态切换和删除。
- 保留照片与集合的关联能力；照片库仍可将照片挂到已有 Theme 或 Workshop。
- 放大关键字号并改善排版层级，兼顾中文阅读、响应式布局和可访问性。
- 不破坏现有照片、集合数据和公开摄影页面。

## 方案

### 导航与页面边界

后台导航调整为：摄影总览、全部照片、上传照片、Themes、Workshops、批量操作、设置。Themes 与 Workshops 各自进入独立的管理视图，而不是通过总览里的筛选器隐式切换。

两个栏目共用可复用的 CollectionManager 结构，但分别传入 `collection_type=theme` 或 `collection_type=workshop`。页面包含栏目说明、数量摘要、搜索/状态筛选、主要新增按钮、内容列表和编辑抽屉。空状态明确提示该栏目尚无内容，并提供新增操作。

### 数据与接口

沿用现有 `photo_collections` 表和 `collection_type` 字段，不新增重复表。复用现有 admin collection API，并补齐前端所需的类型过滤、字段校验和错误状态。集合内容至少包含：slug、中文/英文标题、中文/英文简介、日期/地点信息、封面照片、发布状态。新增与编辑时保持 slug 唯一；删除前给出确认，并由现有数据库关系处理关联照片。

照片上传与编辑中的集合选择继续使用统一数据源，但按 Themes、Workshops 分组显示，避免在“内容管理”与“照片关联”之间产生概念混淆。

### 视觉与排版

采用“编辑感内容层级 + 工作室式操作入口”：米白/炭黑基底、低饱和强调色、明显的页面标题与章节间距。中文正文目标字号 16–18px，辅助信息不低于 14px，按钮和输入控件文字不低于 15px；标题采用更强的字号对比与更舒展的行高。桌面端使用侧栏 + 宽内容区，移动端折叠导航；交互控件保留清晰的 focus 状态和足够点击面积。

### 状态与错误处理

- 首次加载显示骨架或明确加载状态。
- API 失败显示可理解的错误信息和重新加载操作。
- 保存期间禁用重复提交，成功后关闭抽屉并刷新列表/显示状态消息。
- 删除与 slug 冲突都需要明确反馈，不静默失败。
- 无权限或会话过期沿用现有认证处理。

## 测试与验收

- API 测试覆盖按类型读取、创建、更新、删除和非法类型拒绝。
- 组件/交互测试覆盖 Themes 与 Workshops 导航、独立列表、新增入口和筛选结果。
- 回归现有照片上传、编辑、批量操作以及公开 Themes/Workshops 页面。
- 在桌面与窄屏视口检查字号、导航、抽屉和表单可用性。
- 运行项目现有测试与构建，确保没有新增 lint、类型或运行时错误。

## 非目标

- 本次不重做公开摄影页面的信息架构。
- 本次不引入新的 CMS 或第三方内容编辑器。
- 本次不迁移现有照片文件或改变 Supabase Storage 路径。
