# 摄影 CMS 后台设计

## 目标

将当前单张上传页面升级为完整的摄影内容后台。后台需要展示全部已有照片，支持单张/多张/文件夹递归上传、批量编辑、主题和 Workshop 多选关联、上架/下架、单张编辑和删除，并自动完成图片格式处理与双桶存储。

## 内容模型

照片使用现有 `photos` 表保存一份记录和一套 Storage 对象。`published=true` 的照片在网站公开显示，`published=false` 的照片只保留在后台。

照片与集合通过 `collection_photos` 多对多关联：一张照片可以同时属于多个 `theme` 和多个 `workshop`。`photo_collections` 继续保存集合名称、类型、简介和封面信息。后台修改照片元数据时只更新照片本身，不复制文件。

## 后台模块

- 总览：所有照片、已发布、已下架、搜索和状态/集合筛选。
- 上传：单张、多选和文件夹递归读取，显示缩略图、数量、进度、成功与失败列表。
- 批量编辑：统一设置主题、Workshop、地点、日期、中英文说明和发布状态。
- 单张详情：编辑照片 ID、标题、地点、日期、说明、比例和集合归属。
- 集合管理：选择多个主题和多个 Workshop；第一版可复用现有集合，不强制新增集合创建界面。
- 发布管理：上架/下架只修改 `published`，不删除图片。

## 上传流程

1. 用户选择文件、拖拽多个文件，或选择文件夹并递归读取图片。
2. 页面显示待上传缩略图，允许移除单个待上传文件。
3. 用户填写并批量应用元数据、选择多个主题/Workshop 和发布状态。
4. 前端逐张调用服务端上传 API，并显示总体与单张进度。
5. 服务端验证管理员身份、文件类型、大小和路径，自动纠正 EXIF 方向。
6. 服务端生成适合网站展示的 WebP 预览图，上传到 `photo-previews`；原始文件按原格式上传到私有 `photo-originals`。
7. 写入或更新 `photos`，再幂等写入 `collection_photos` 关联。
8. 失败项单独显示并可重试；已成功项不会重复上传。

## 图片处理与存储

- 支持 JPG、PNG、WebP、HEIC、TIFF 等由图片处理库支持的格式；不支持的格式给出明确错误。
- 预览图自动旋转、限制最大展示宽度并转为 WebP；用户不需要手动压缩。
- `photo-previews` 公开读取；`photo-originals` 保持私有。
- 公开 API 和前端只接收预览 URL，不返回原图路径。

## 页面结构

后台工作台包含：

- 顶部导航和筛选：全部、已发布、已下架、主题、Workshop、搜索。
- 照片网格：缩略图、ID、标题、地点、发布状态和集合标签，以及编辑、上/下架、删除操作。
- 批量操作栏：选择多张后批量设置元数据、集合和发布状态。
- 上传面板：文件/文件夹选择、待上传预览、统一信息表单、进度和失败重试。
- 编辑面板：单张照片全部信息和集合复选框。

## 权限与失败处理

- 只有 `ADMIN_EMAILS` 中的 Supabase Auth 用户可以访问后台和管理 API。
- 未配置白名单或邮箱不匹配时拒绝访问。
- 单张上传失败不影响同批其他文件。
- 预览、原图或数据库写入失败时清理本次已上传对象，并显示失败原因。
- 下架不删除数据库记录或 Storage 对象。
- 永久删除必须二次确认，并同时处理数据库记录和两个 Storage 对象。

## 验收标准

- 后台能看到现有已迁移照片，而不是只有新上传内容。
- 单张、多张和文件夹上传都能递归处理并显示进度。
- 批量元数据和多集合关联正确保存。
- 同一张照片可以同时出现在多个主题和 Workshop 中。
- 上架/下架立即影响公开网站显示，但不删除后台内容。
- 编辑后的信息和集合关系刷新后仍然保留。
- 任意支持格式上传后无需手动压缩，网站使用自动生成的预览图。
- 原图保持私有，公开接口无原图路径。
- 失败项可重试，不产生孤儿对象或重复关联。
