# 摄影后台管理页面设计

## 目标

为项目增加一个受 Supabase 邮箱登录保护的摄影后台，第一版专注单张照片上传与基本信息维护。后台自动生成公开 WebP 预览图，将原图保存在私有 Storage 桶，并同步写入 `photos` 表。

## 范围

第一版包含：

- Supabase 邮箱密码登录
- `/photography/admin` 受保护页面
- 单张图片选择或拖拽上传
- 图片预览、格式与大小提示
- 编辑照片 ID、中文/英文地点、日期、中文/英文说明和比例
- 服务端生成 WebP 预览图
- 上传公开预览图到 `photo-previews`
- 上传私有原图到 `photo-originals`
- 写入或更新 `public.photos`
- 已上传照片列表和基础编辑/删除入口
- 上传进度、失败提示和失败清理

暂不包含批量上传、摄影集合关联、项目/Journal/课程管理和多管理员角色。

## 用户流程

1. 用户打开 `/photography/admin`。
2. 未登录时显示 Supabase 邮箱登录表单；已登录时进入照片管理界面。
3. 用户选择一张图片，页面显示预览和文件信息。
4. 系统根据文件名生成可编辑的照片 ID，用户填写其余元数据。
5. 页面调用服务端上传 API。
6. 服务端检查登录状态、格式、大小和路径安全性，生成 WebP 预览图。
7. 服务端先上传预览图，再上传原图，最后写入或更新 `photos` 表。
8. 成功后返回预览地址和照片记录；失败时显示明确状态，并清理已上传的临时对象。

## 页面结构

页面沿用现有网站的米白、黑色、衬线标题和简洁卡片风格。

- 上传区：拖拽/选择文件、预览、文件信息、上传按钮和进度。
- 信息区：照片 ID、地点中英文、日期、说明中英文、比例和校验提示。
- 列表区：已上传缩略图、ID、地点、状态、编辑和删除操作。

删除原图或数据库记录必须二次确认。相同 ID 使用更新模式，避免重复记录。

## 技术架构

浏览器使用 Supabase 公共 URL 和 publishable/anon key，仅负责登录状态、表单和调用服务端 API。`SUPABASE_SECRET_KEY` 只存在服务端环境变量中。

建议新增：

- `app/photography/admin/page.jsx`：后台页面
- `app/api/admin/photos/route.js`：上传和更新接口
- `app/api/admin/photos/[id]/route.js`：查询、编辑或删除接口
- 服务端图片处理与 Storage 辅助模块
- Supabase Auth 客户端/服务端会话辅助

接口写入顺序为：生成预览 → 上传公开预览 → 上传私有原图 → 写入 `photos`。数据库写入失败时删除本次上传的 Storage 对象，避免留下孤儿文件。

## 安全要求

- 未登录用户不能访问后台页面或上传接口。
- 公开接口只返回预览路径，不返回 `original_path`。
- `photo-previews` 允许公开读取；`photo-originals` 保持私有。
- 只允许常见图片格式，并限制单张文件大小。
- 文件名和 Storage 路径必须经过清理，拒绝绝对路径和路径穿越。
- 删除操作必须二次确认。
- 继续使用 `photos` 表 RLS；服务端管理密钥不能进入客户端 bundle。

## 验证标准

- 未登录访问后台被拦截。
- 未登录调用上传 API 被拒绝。
- 登录后能上传一张图片并看到成功状态。
- 预览图能公开读取，原图不能匿名读取。
- `photos` 表包含正确的预览路径和私有原图路径。
- 更新同一 ID 不产生重复记录。
- 上传或数据库写入失败时不会留下未追踪的孤儿对象。
- 现有内容 API 仍不会泄露原图路径。
- 单元测试和生产构建通过。
