# 摄影后台验证与操作说明

## 环境配置

1. 在部署环境中配置 `NEXT_PUBLIC_SUPABASE_URL`、`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` 和服务端使用的 `SUPABASE_SECRET_KEY`。
2. 配置 `ADMIN_EMAILS` 为允许进入摄影后台的 Supabase 用户邮箱，多个邮箱用英文逗号分隔，例如 `ADMIN_EMAILS=you@example.com`。不要把真实邮箱提交到 `.env.example` 或代码仓库。
3. 确认 Supabase Storage 中存在 `photo-previews` 与 `photo-originals` 两个 bucket。预览可公开读取；原图应保持私有，仅由服务端受控访问。

## 登录与后台入口

1. 打开 `/photography/login`，使用已在 Supabase 创建且邮箱出现在 `ADMIN_EMAILS` 中的账户登录。
2. 登录后进入 `/photography/admin`。未登录用户应被 middleware/API 拒绝；已登录但不在白名单中的用户应收到管理员权限未配置提示。
3. 点击“退出登录”后，应返回登录页；退出失败时页面应保留并显示错误提示。

## 上传、编辑、删除流程

### 上传

1. 选择一张 JPG、PNG 或 WebP（当前后台按单文件上传设计）。
2. 填写 Photo ID、标题、地点、日期、比例及中英文说明。
3. 点击“上传并保存”，确认按钮进入“上传中…”状态并被禁用。
4. 成功后，新照片出现在列表顶部并显示“照片已上传”；失败时显示 API 返回的错误或通用失败提示。
5. 上传失败时应检查预览与原图是否按服务端逻辑清理；本验证不执行真实上传。

### 编辑

1. 在照片列表中点击“编辑”，修改标题、地点、日期或比例。
2. 点击保存，成功后列表立即更新并显示“已保存”；接口返回的校验错误应直接显示给用户。

### 删除

1. 点击“删除照片”，确认浏览器二次确认对话框。
2. 取消确认不应发起请求；确认后，成功时照片从列表移除并显示“照片已删除”。
3. 删除失败（包括记录已删但 Storage 清理失败）时，应显示服务端错误；本验证不执行真实删除。

## 原图私有说明

公开摄影页只使用预览图 URL。`photo-originals` 用于保存原始文件，不应配置为公开 bucket，也不应把原图 URL 写入公开内容或客户端列表。需要原图时，应新增服务端鉴权下载流程并返回短时 signed URL；当前后台验证仅确认上传与清理路径，不下载或暴露原图。
